## Context

The project currently contains only `README.md` and `env.example` — no scaffold exists yet. This plan therefore covers bootstrapping the standard project structure and then delivering a single, clean home page whose centerpiece is a large "Hello, World!" heading, centered vertically and horizontally, on a white/off-white background with no navigation bar, no footer, and no interactive elements.

## Steps

1. **Create `package.json`**
   - Define the npm package (ESM, `"type": "module"`) with scripts: `dev` (vite), `build` (tsc + vite build), `preview` (vite preview).
   - Dependencies: `react`, `react-dom`, `@tanstack/react-router`.
   - Dev dependencies: `vite`, `@vitejs/plugin-react`, `@tanstack/router-plugin`, `typescript`, `tailwindcss`, `@tailwindcss/vite`, `@types/react`, `@types/react-dom`.
   - Expected outcome: `npm install` resolves a complete, working toolchain.

2. **Create `vite.config.ts`**
   - Register `@tanstack/router-plugin/vite` (file-based routing, default conventions) and `@tailwindcss/vite` alongside the React plugin.
   - Configure the `@` path alias pointing at `src/` (mirrored in `tsconfig.json` paths).
   - Expected outcome: Vite dev server starts; the router plugin auto-generates `src/routeTree.gen.ts` from `src/routes/`.

3. **Create `tsconfig.json`**
   - Standard strict TypeScript config for a Vite React app (`"jsx": "react-jsx"`, bundler module resolution, path alias `@/*` → `src/*`).
   - Expected outcome: `tsc` type-checks the project with no errors.

4. **Create `index.html`**
   - Minimal HTML shell at the project root with a `<div id="root">` mount point, a `<script type="module">` pointing at `/src/main.tsx`, a viewport meta tag for mobile responsiveness, and the document title "Hello, World!".
   - Expected outcome: Browser loads the app entry.

5. **Create `src/styles/global.css`**
   - First line MUST be exactly `@import "tailwindcss";`.
   - Optionally set the document background to white/off-white and the default text color to a dark neutral via Tailwind theme tokens or a plain `body` rule; no other global styles.
   - Expected outcome: Tailwind v4 utilities are available app-wide; page background is light and text is dark neutral by default.

6. **Create `src/main.tsx`**
   - Import `src/styles/global.css` once.
   - Create the TanStack Router instance from the generated route tree and render `RouterProvider` into `#root` via `createRoot`.
   - Expected outcome: App boots and router context is available to all routes.

7. **Create `src/routes/__root.tsx`**
   - Root route component rendering only `<Outlet />` (plus any required devtools-free shell). Do NOT add a header, nav, footer, or any other chrome — the requirement is zero extra UI.
   - Expected outcome: Child routes render without any surrounding layout elements.

8. **Create `src/routes/index.tsx`**
   - Home route (`/`) whose component renders a full-viewport-height (minimum) flex container that centers its child both vertically and horizontally.
   - The child is a single `h1` reading "Hello, World!", styled with a large, responsive Tailwind font-size scale (e.g., noticeably larger on medium-and-up breakpoints than on mobile), semibold/bold weight, tight tracking, and dark neutral color; generous whitespace around it, nothing else on the page.
   - Expected outcome: Visiting `/` shows only the big "Hello, World!" heading, centered, looking clean on both mobile and desktop.

9. **Verify generated and untouched files**
   - Confirm `src/routeTree.gen.ts` was generated by the router plugin and is never hand-edited.
   - Leave `README.md` and `env.example` untouched (no starter content exists to clean up; the scaffold itself is the only content).
   - Expected outcome: No leftover demo/boilerplate UI anywhere in the app.

10. **Smoke-test the build**
    - Run the dev server and the production build; verify `/` renders the heading with no console errors, no layout shift, and the light background fills the viewport on all screen sizes.
    - Expected outcome: Clean dev run and successful `build` + `preview`.
